# 长文分段与来源覆盖检查

当前提供确定性本地分段、串行请求、逐段候选保存与来源编号检查。**来源映射是模型声明，不证明语义忠实、事实正确或跨段人物一致。**完整状态见 [功能总清单](FEATURES.md)，服务配置见 [文本 AI 配置](AI_SETUP.md)。

## 操作

1. 输入文案、选择类别和补充要求，在文本面板下方「长文分段与覆盖检查」点击「预览改写分段」或「预览分镜分段」。规划只在本地执行，零模型请求。
2. 展开每段检查原文及 `[start, end)` 偏移，核对段数。偏移从 0 开始，按 UTF-16 计数，包含空白与标点；不是 Token 数或费用。
3. 配好文本服务后，点击「确认处理未完成段」或「仅处理此段」。确认框展示地址、模型、所选段数与最多请求次数；每段最多一次请求、输出上限 4096 Token，**价格与实际用量未知，可能计费**。拒绝确认不请求。
4. 客户端先保存检查点，再按原文顺序串行提交。每段结果返回后再次保存；首个失败或映射异常即停止，已成功段保留，不自动重试或追加请求。
5. 查看逐段结果和遗漏／重复／越界／顺序异常。保存项目后重开，或恢复已落盘草稿后，可重新确认补跑未完成段；成功段不重发。取消准备中的请求可做到零提交；取消在途请求不保证服务端停止计费。
6. 全部结果及映射有效后，人工审阅并点击「整体采用分段结果」。改写替换项目文案、进入最近 100 条改写历史，现有分镜不变；分镜采用需确认替换影响，并支持最近一次会话内分镜替换撤销。

补跑只允许未完成／失败段；若不满意已完成段，需明确重新规划，已有候选会被替换，可能增加调用。重新规划有候选时会确认。原文、类别或补充要求改变后，旧计划过期，不能补跑或采用；需重新规划。

## 规划与覆盖规则

- 项目文案最多 30,000 UTF-16 字符。按 `。！？!?` 与换行形成原文单元，过长单元拆至最多 180 字符，不切开 Unicode 代理对；保留原始空白、标点及偏移。
- 相邻单元按预算组合：分镜每段最多 600 字符，改写最多 1200 字符。不是模型自动决定分段，也不是 Token 精确估算。
- 每段原文单元从 1 编号，要求结果 JSON 提供 `sourceIds`：改写为整段映射，分镜为逐镜映射。检查所有编号恰好出现一次，且不越界、不乱序；映射总条目最多 2400。
- 无映射、响应截断、结构无效或超预算不当作成功；普通短文入口遇到需分段的原文也会拒绝，不暗中增加收费调用。
- 合并分镜超过 100 镜、改写超过 30,000 字符时拒绝整体采用，不截断、不静默丢段。可缩短原文或人工分项目制作；本轮无自动跨项目拆分。

## 保存及限制

计划、原文、补充要求、逐段结果／错误及来源映射保存在可选 `Project.textWork`，随手动项目与独立自动草稿保存；旧项目无需该字段。整体采用或明确丢弃后清除 `textWork`，不删除任务结果 JSON／文件。采用后的分镜不增加永久来源字段；如需保留映射，应在采用前另存项目副本。

每段只发送该段原文、类别、补充要求、段序号及单元编号，**不共享其他段正文或先前结果**；没有跨段人物设定／叙事上下文保证，也不额外调用模型审核。编号齐全不代表模型实际保留了每项含义，仍需逐段人工对照。空白独立成段时会被请求参数拒绝并停止，不会静默丢掉空白后继续；可人工调整文案后重新规划。

成功结果后置保存失败时，界面仍保留候选并停止后续请求，但未落盘结果在崩溃后可能丢失。中断状态无法推断远端计费；补跑前先核查草稿、任务记录与服务端情况。没有跨本地／远端的原子事务、持久化幂等或精确费用账单。

本轮选择确定性分段及同次响应的来源映射，便于核对原始范围、限定调用次数且不新增模型审查费用。备选是共享全文上下文或单独语义审查，可能改善连贯性／发现含义遗漏，但会增加上下文、成本及新的失败路径，需另行确认和真实样例验收。
