# 图片 AI 配置与验证

## 范围与协议

`0.3.0` 提供独立图片配置、单镜生图、缺图批量和全部重新生成；逐张确认采用，不静默覆盖分镜。当前只完成本机模拟验收，**未调用真实模型、未验证实际计费或真实 macOS 钥匙串**。

采用 OpenAI 兼容 `POST /images/generations`，每镜发送：

```json
{
  "model": "用户配置的模型标识",
  "prompt": "当前镜头的绘图提示词",
  "n": 1,
  "size": "1024x1024",
  "response_format": "b64_json"
}
```

接受 `data` 数组恰好一张图片的 `b64_json`，亦接受与 API **协议、主机、端口完全相同**的图片 URL。URL 下载不发送 API Key、不跟随重定向，可包含服务提供的签名查询参数，但不回显或写入项目。拒绝跨域 CDN、账号密码或片段；这会限制某些服务，不能宣称所有 OpenAI 兼容模型均可直接使用。

当前选择这套窄协议，便于复用已有请求和密钥边界；备选是供应商原生接口或异步轮询，但需另行适配参数、任务状态、取消和计费。没有静默回退到其他协议、模型或尺寸。

## 配置与操作

1. 保存当前项目，重启新版客户端；开发模式运行 `npm run dev`。
2. 打开「图片模型设置」，填写基础地址、模型和 Key；不要附加 `/images/generations`。
3. 配置与文本模型独立，不会复用文本 Key；保存本身不联网。无独立的“极短图片测试”，请主动生成一张图片验证，可能产生正常生图费用。
4. 编辑右侧「绘图提示词」。生图只使用这个字段，不自动拼接文案、画面描述、补充要求或旧图片。
5. 在生图面板选择尺寸。支持选择 `1024x1024`、`1024x1536`、`1536x1024`、`1024x1792`、`1792x1024`；服务是否接受需真实联调，返回图片不保证等于请求尺寸，导出仍按项目画布居中裁切。
6. 点击「生成当前分镜图片」「批量生成缺图分镜」或「重新生成全部分镜图片」，确认目的地址、模型、尺寸与最多调用数量。
7. 查看候选，逐张点击「采用此图片」；提示词改变或原分镜被删除后，旧候选不能采用。丢弃只移除界面中的候选，不删除文件。
8. 保存项目，再使用既有导出流程生成 MP4。

公网 API 必须 HTTPS，仅 loopback 本机测试地址允许 HTTP。超时每镜 5–180 秒，覆盖请求、下载及落盘前检查；图片解码期间无法立即打断 Sharp，但会在解码完成后检查取消／超时，避免继续落盘。

## 批量、失败与成本

- 每批最多 100 镜，每镜一次请求、一次最多一张，始终串行。
- 范围内提示词不能为空；缺图模式按 `imagePath` 是否为空判断，不会重新生成已有路径但文件缺失的镜头，此类情况可用单镜生成或手动重新关联。
- 普通服务错误、非法图片和超时按单镜失败处理，后续镜头可继续；认证失败、限流或落盘失败停止后续调用。
- 取消中止当前网络请求，不再启动后续镜头，保留本批已成功候选；不自动重试，也不会后台补齐。
- 取消也覆盖保存草稿的准备阶段，此时取消后不提交生图请求。每镜保留最新成功候选及最近一次失败，失败不会覆盖成功；新成功替换同镜旧候选与失败。未采用候选仍不随项目恢复。
- 失败后可选择对应镜头主动重新生成，需再次确认且可能再次计费；服务端已经生成但下载失败的图片不会自动恢复下载。
- 显示的是调用上限与已处理镜头数，不是价格或供应商账单；暂不记录图片服务 Token、价格或持久化调用台账。
- 取消／超时不保证服务端停止处理或计费。`0.6.0` 保留逐镜任务／文件记录并可在重启后核验，不自动回填候选、重新下载或重发；登记失败保留成功候选并停止后续镜头。新增任务图片的预览、选镜及确认关联，不重发模型请求，见 [产物重新关联](产物重新关联.md) 与 [恢复说明](RECOVERY.md)。
- 生图与文本 AI、导出任务互斥；现有成功素材不因失败或取消而删除。

## 文件、版本与安全边界

- Key 沿用 `safeStorage` 加密和 `0600` 文件权限，独立存入用户数据目录的 `image-settings.json`；更换地址必须换 Key 或删除旧 Key。不回显、不写入项目，无明文兜底。
- 响应 JSON 上限 28 MiB，原图／归一化 PNG 上限 20 MiB，解码上限 4000 万像素，仅接受静态 PNG、JPEG、WebP；拒绝 SVG、动画和损坏图片。不是完整的媒体安全审计。
- 主进程将图片归一化为 PNG，使用随机文件名及临时文件原子落盘，不采用服务端文件名，不在渲染页加载远程图片。
- 图片保存到用户数据目录 `generated-images/`，缩略图用于界面；配置目录实际位置由 Electron 决定。
- 采用或手动替换图片时保留旧图引用，最多 20 个版本；版本保存文件路径、生成提示词、模型和时间。旧项目没有此字段时仍可打开。
- 在「当前分镜图片版本」切回旧图只读本机文件，不发生成请求、不覆盖当前绘图提示词；缺失版本读取失败时当前图片保持不变。
- **版本和项目不包含图片本体。** 移动图片、删除用户数据或跨设备仅复制项目 JSON，都可能造成素材缺失；未采用候选不随项目恢复。
- 丢弃候选、超出版本引用上限或关闭项目不自动删图。暂未实现存储配额、孤立文件清理、素材打包和持久化任务库；大量生图前注意磁盘空间，不要直接批量删除可能仍被其他项目引用的图片。

## 验证

```bash
npm run test:images
npm run test:images-desktop
```

- 11 项本机模拟测试：参数、Base64、同源下载／无凭据、错误不回显、格式及大小限制、批量部分成功、认证／限流停止、取消、超时、落盘失败、版本上限和独立配置。
- 桌面测试：真实 Electron 中的配置／确认、候选／采用／丢弃／过期保护、旧图切换、部分失败、保存重开、缺图批量、取消保留成功、任务互斥及新项目隔离；使用模拟图片实际导出 9 秒、720×1280、H.264／AAC MP4。
- 测试只调用本机临时 HTTP 服务，桌面密钥接口使用测试替身，避免触发真实钥匙串授权；生成图片是本地色块，不是对真实模型质量的验收。
- 本轮 `npm run test:hardening` 与 `npm run test:hardening-desktop` 另验证准备期取消零请求、成功后连续失败仍可采用、新成功清除旧失败及跨项目隔离；详细结果见 [功能验证记录](FEATURES.md)。

真实供应商的协议、尺寸支持、输出质量、费用、超时表现、钥匙串授权／重启解密、正式安装包仍需单独验收。
